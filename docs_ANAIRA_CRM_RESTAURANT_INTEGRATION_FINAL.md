# Anaira CRM ↔ Anaira Restaurant SaaS — Final Integration Hub

## Locked architecture

- CRM and Restaurant SaaS remain standalone products.
- No direct DB-to-DB dependency.
- Cross-product communication uses versioned API + events + webhooks.
- Restaurant SaaS is operational source of truth.
- CRM is customer/relationship source of truth.
- Integration Hub owns authentication, business mapping, permissions, field mapping, sync, events, webhooks, retry, idempotency, reconciliation, logs and health.
- POS must continue if CRM or the network is unavailable.

## Super Admin control

Both applications expose a dedicated Super Admin Integration Hub:

- CRM: `/super-admin/integrations/restaurant`
- Restaurant SaaS: `/super-admin/integrations/anaira-crm`

Super Admin controls:

- Connect / disconnect / reconnect
- Business / restaurant mapping
- Connection enable/disable
- Capabilities
- Event allowlist
- Field mapping JSON
- Sync mode
- Retry enablement
- Max retry attempts
- Exponential-backoff base seconds
- Dead-letter policy
- Webhook/event policy
- Health test
- Manual sync verification
- Reconciliation
- Integration logs
- Plugin/integration visibility through Super Admin control center

Mutation APIs reject non-Super-Admin integration configuration.

## Credential pairing

There are two separate machine credentials.

### 1. Restaurant Integration Key (`anr_...`)

Generated by Restaurant SaaS Super Admin. It authenticates:

`CRM → Restaurant SaaS`

The Restaurant SaaS stores only a SHA-256 hash. CRM stores the raw value encrypted.

### 2. CRM Callback Key (`crm_...`)

Generated by CRM Super Admin. It authenticates:

`Restaurant SaaS → CRM webhook/events`

CRM stores the callback key encrypted. Restaurant SaaS stores the callback key encrypted.

Raw keys are returned only on generation/rotation.

## Pairing sequence

1. Open Restaurant SaaS Super Admin → Anaira CRM Integration Hub.
2. Select the restaurant.
3. Generate / Rotate Restaurant Integration Key.
4. Copy the `anr_...` key.
5. Open CRM Super Admin → Restaurant SaaS Integration Hub.
6. Select the matching business/restaurant.
7. Enter Restaurant SaaS Base URL.
8. Paste the `anr_...` Restaurant Integration Key.
9. Generate / Rotate CRM Callback Key.
10. Copy the `crm_...` key.
11. Save the CRM-side integration.
12. Return to Restaurant SaaS Super Admin.
13. Enter CRM Base URL.
14. Paste the `crm_...` CRM Callback Key.
15. Save the integration.
16. Run Test Connection on both sides.
17. Run Live Sync Check / Reconciliation.

## Cross-product flows

### Catalog

Restaurant SaaS menu → API snapshot/event → CRM marketplace consumes canonical catalog.

No second authoritative menu master is created.

### Marketplace order

CRM marketplace → Restaurant SaaS integration bridge → canonical POS order creation → KOT/KDS → payment/operations → order event → CRM customer/order history.

### Customer 360

Restaurant order/customer context → CRM event receiver → customer upsert → restaurant visit → revenue/visit history.

### Payments/refunds

Operational payment/refund remains Restaurant SaaS-owned and is emitted as integration events for CRM history.

### Delivery/reservations/inventory

Operational state remains Restaurant SaaS-owned and can be propagated through the event contract and capability allowlist.

### CRM intelligence

Customer 360, segments, VIP, loyalty, offers, reviews, marketing and automation remain CRM-owned and can be exposed to Restaurant SaaS through the integration contract.

## Reliability

- Idempotency keys
- Duplicate event detection
- Duplicate marketplace order prevention
- Event inbox
- Webhook event persistence
- Failed event persistence
- Retry queue
- Exponential backoff
- Dead-letter state
- Manual retry endpoint
- Health status
- Reconciliation records
- Integration logs

Retry endpoints:

- CRM: `POST /api/integrations/restaurant/retry`
- Restaurant SaaS: `POST /api/integrations/anaira-crm/retry`

They accept a Super Admin bearer token or configured `CRON_SECRET`.
