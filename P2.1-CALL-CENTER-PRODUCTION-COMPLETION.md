# P2.1 Call Center — Implementation / Verification

## Flow
Incoming Caller → Phone Identification → Customer 360 → Previous Orders → Quick Reorder → Delivery → Callback → Call History → Agent Assignment → Resolve

## Implemented
- `p2_1_call_sessions` — restaurant-scoped call session with idempotency key.
- `p2_1_call_events` — immutable event/history trail for identification, assignment, callback, delivery, reorder and resolve events.
- RPCs: caller identification, call creation, agent assignment, callback scheduling, call resolution.
- RLS on P2.1 tables.
- Server-side restaurant isolation and staff permission checks in `/api/call-center`.
- `/dashboard/call-center` admin/staff UI.
- Caller search and Customer 360 summary.
- Previous order history.
- Quick Reorder handoff into existing `/order` POS; items are loaded into cart for review before billing.
- Delivery request event and address capture; existing POS delivery workflow remains the final order/delivery execution point.
- Callback scheduling.
- Agent assignment.
- Call history and resolution.
- Existing `/dashboard/calling` Calling Device remains intact.
- Existing `/dashboard/customers` Customer 360 remains intact.
- Sidebar navigation added for Call Center.

## Financial / Safety Controls
- Quick reorder does not finalize or collect payment automatically.
- Existing POS pricing, modifiers, taxes, offers and payment flow remain authoritative.
- Restaurant ID is checked server-side.
- Agent must belong to the same restaurant.
- Create call requires an idempotency key.
- Existing POS/QR/Cashfree/printer/offline code was not removed.

## Verification
- JavaScript syntax checks passed for P2.1 API/page and modified POS page.
- Supabase SQL executed successfully and P2.1 objects/RPCs were verified.
- Full Next.js production build could not be run in this ZIP because dependencies/node_modules are not installed (`next: not found`). Run `npm install` followed by `npm run build` in the project environment before production deployment.
