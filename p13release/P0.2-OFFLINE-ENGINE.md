# P0.2 — Native Offline Engine & Conflict Recovery

Implemented on top of P0 Market Parity Core.

## Native Android recovery
- Android WorkManager periodic sync (15 minute minimum cadence) with network constraint.
- One-time native sync is triggered whenever the authenticated WebView session is registered.
- Auth token is encrypted at rest with an Android Keystore AES-GCM key.
- Logout clears the native sync session.
- Worker operates without the WebView being alive and reconciles queued orders, billing finalization and delivery changes.
- Cloud pull cursor is persisted locally.
- DELETE sync events remove the local record instead of being treated as an upsert.
- Local-newer/cloud-newer conflicts are persisted locally and sent to the existing server conflict endpoint.

## Web/PWA fallback
IndexedDB remains the fallback local database. The existing foreground sync remains active for web/PWA and Android WebView.

## Safety
- No business data is deleted by this phase.
- Existing local records are preserved during native DB version upgrade.
- Existing payment/refund idempotency from P0 remains intact.
- WorkManager retries transient failures; authentication failures stop the native retry loop until the user signs in again.

## Remaining P0 work
This phase makes native recovery real, but full multi-entity offline replication and automatic server-side conflict resolution policies remain a later P0/P1 hardening item.
